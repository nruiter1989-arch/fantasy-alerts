# Lineup alert rules (shared by all 5 lineup alerts)

This file is Niek's own rules file for his fantasy lineup alerts. Each scheduled alert (TNF, Sunday early, Sunday late, SNF, MNF) first works out the season, week and which game(s) are in its slate (its STEP 0 and STEP 1), then loads this file and follows everything below for that slate. "This slate" below always means the game(s) the calling alert identified in its STEP 1.

Everything else in this file still applies.

Compose one alert covering both his leagues (it goes onto Niek's Lineup Alerts page — see Delivery at the end):

- League ID 1368762222599213056 (Curacao Baller League)

Use the FFC (League Loom) connector. For each league, call fantasy_get_my_team (or fantasy_get_rosters + fantasy_get_matchups) to get Niek's current starters and bench for this week. Identify which of his STARTERS are in a game belonging to THIS slate (the game(s) listed in STEP 1 of the alert that loaded this file) — cross-reference each starter's NFL team (proTeam) against those games.

For each such starter, report his active/game status (Sleeper injuryStatus — already visible on the roster entry returned above; active/questionable/doubtful/out/inactive) and flag clearly if he is NOT expected to play.

FantasyPros injury check for questionable starters: once the status lines above are known, collect every starter in this slate whose status is Questionable or Doubtful (in either league) and call mcp__FantasyPros__injury_status ONCE with all of their FULL names comma-separated (first and last name, e.g. "Brock Bowers, Tee Higgins" — last names alone don't resolve). For each player it knows, it returns practice_details (probability_of_playing as a decimal, and practice_1/practice_2/practice_3 = this week's practice participation, e.g. Full/Limit/DNP) plus player_news. Append a short note to that starter's status line in this style: "Questionable (12.4) — FP: 48% to play, practice Limited/Limited/DNP; <news gist in at most ~12 words>". Round the probability to a whole percent. Don't call it for Active or Out players. If a player isn't in the result, or the FantasyPros connector is unavailable or errors, leave his status line as it is — never mention the missing check and never let it block the alert.

Then add a second line per starter depending on his position:

Before picking a nearest replacement anywhere below (offense FLEX/SUPER_FLEX/dedicated-slot pools, or the IDP pool), filter the candidate pool to bench players who are actually still swappable right now: check each candidate's lineupLock (from fantasy_get_my_team/fantasy_get_rosters) and drop anyone whose lineupLock.status is "locked", or whose gameStatus is "final" or "in_progress" — his own game has already started, so Niek can't sub him in this week no matter how good his projection looks, and suggesting him isn't actionable. Only compute distances and pick the nearest replacement among bench players who are still not_started/unlocked. If this empties a pool entirely, fall back to "no bench option with a projection" (or note plainly that everyone in his pool is already locked) rather than naming a locked player.

For OFFENSE starters (QB, RB, WR, TE) — get THREE independent weekly projections and average them (Sleeper's own, FantasyPros' expert consensus and StatHead's model, so one source's odd number can't carry a decision on its own):
  (a) Sleeper's own projection: call mcp__Sleeper_Remote_MCP__get_projections once with season=<season from STEP 0>, week=<week from STEP 0> (default positions QB,RB,WR,TE). Each row has the projected stat line (pass_yd, pass_td, pass_int, rush_yd, rush_td, rec, rec_yd, rec_td). Match players by name+team. Players Sleeper doesn't expect to play (backups, inactives) are left out of this list.
  (b) FantasyPros' projection: call mcp__FantasyPros__get_projections with projection_type="weekly", week=<week from STEP 0>, once per position: QB (limit 80), RB (limit 130), WR (limit 220), TE (limit 120). Stat fields: pass_yds, pass_tds, pass_ints, rush_yds, rush_tds, rec_rec (receptions), rec_yds, rec_tds. Match by name+team (FantasyPros writes Jacksonville as JAC and may add suffixes like "II"/"Jr.").
  For (a) and (b), do NOT use their ready-made point totals — both of Niek's leagues score interceptions at -1 (not -2), and Dutch Dynasty League scores passing touchdowns at 6 (not 4), so recompute each player's points from the stat line with the formula for the league you're reporting on:
    - Dutch Dynasty League (1317597867963072512): points = pass_yd*0.04 + pass_td*6 + pass_int*(-1) + rush_yd*0.1 + rush_td*6 + rec*1 + rec_yd*0.1 + rec_td*6
    - Curacao Baller League (1368762222599213056): points = pass_yd*0.04 + pass_td*4 + pass_int*(-1) + rush_yd*0.1 + rush_td*6 + rec*1 + rec_yd*0.1 + rec_td*6
  (Non-QBs rarely have passing stats, so both formulas reduce to the same line for them — this mainly matters for QBs.)
  (c) StatHead's projection: call mcp__Stathead__get_weekly_projections once with week=<week from STEP 0>, scoring=ppr, limit=1000, output_format=jsonl (no position filter, no player_name) and use each player's "pts" (already full PPR, standard scoring — it has no raw stat line to recompute). Note: mcp__Stathead__get_sleeper_projections is NOT Sleeper's data any more (it returns this same StatHead model) — never use it as a separate source.
  Combining: average the sources that returned data this run. Backups count as zero, not as missing: if StatHead marks a player status=backup (or his availability makes him 0), use 0 for StatHead; if Sleeper's list loaded but the player isn't in it, use 0 for Sleeper. Only if a whole source failed to load (call error) do you leave it out of the average. If all three fail for a player, say "no projection available". Show the final average, rounded to one decimal, as the player's projected points everywhere below.

Both leagues' roster_positions include exactly these DEDICATED slots: 1 QB, 2 RB, 2 WR, 1 TE — plus 2 FLEX slots (RB/WR/TE-eligible) and 1 SUPER_FLEX slot (QB/RB/WR/TE-eligible) that aren't tied to one position. Which bench players are actually eligible to replace a given starter depends on which kind of slot he's in — a swap is only real if the resulting lineup can still fill every dedicated slot:
  - Starter in a FLEX or SUPER_FLEX slot: pool = all bench players eligible for that slot (RB/WR/TE for FLEX; QB/RB/WR/TE for SUPER_FLEX), pooled together. Swapping him never threatens the dedicated counts, since he wasn't filling one.
  - Starter in a DEDICATED slot (QB, RB, WR, or TE): first check whether Niek currently starts a "spare" player of that same position already sitting in a FLEX or SUPER_FLEX slot — i.e. does he start MORE players of that position across all slots than the dedicated minimum requires (1 QB, 2 RB, 2 WR, 1 TE)? If yes, that spare could slide into the vacated dedicated slot, so the broader FLEX-eligible pool above is valid for him too. If no such spare exists, ONLY a bench player of that exact same position is a valid nearest-replacement candidate — a different-position bench player can't actually be started there without leaving that dedicated slot unfillable, so exclude every other position from his pool.
  Show the single NEAREST replacement from the correctly-scoped pool — the bench player whose averaged points (computed the same way) are closest in absolute value to the starter's (whether higher or lower) — with name, position, and points. Always show this line; only say "no bench option with a projection" if nobody in the correctly-scoped pool has one. Mark it as a possible upgrade if the bench player's points are actually higher.

For IDP starters (LB, DB, DL) — this only applies in Dutch Dynasty League (Curacao has no IDP roster spots). Do NOT use Sleeper's projections feed or StatHead's weekly projections feed for these — neither reflects this league's IDP scoring. Instead, for each IDP starter AND each bench DL/LB/DB player on the same fantasy team, call mcp__Stathead__get_projections once per player with player_name=<exact name>, position=<their position: DL, LB, or DB>, fields="player_name,team,games,solo,assist,tfl,sack,qb_hit,pd,def_int,ff,fum_rec,def_td,safety,weeks_2plus_sack,weeks_3plus_pd,weeks_10plus_tackle" to get their season projection components (skip a player silently if not found — rare/deep bench/rookie — and note "no projection available" only if he'd otherwise be the closest bench option).

Compute each player's PER-GAME custom IDP projection using Niek's Dutch Dynasty League's actual IDP scoring rules (StatHead's own generic IDP rollup does NOT match these — it has no credit for forced fumbles, pass deflections, or QB hits, and different sack/INT weights):
  weekly_points = (solo/games)*1 + (assist/games)*0.5 + (tfl/games)*2 + (sack/games)*4 + (qb_hit/games)*1 + (def_int/games)*4 + (fum_rec/games)*2 + (ff/games)*3 + (safety/games)*2 + (def_td/games)*6 + (pd/games)*2 + (weeks_10plus_tackle/games)*1 + (weeks_2plus_sack/games)*1 + (weeks_3plus_pd/games)*1
(This uses each player's season-average per-game rate as the week's estimate — StatHead's own docs note IDP week-to-week matchup swings are small, a few percent and near-zero for DB, so a flat season rate is a reasonable weekly proxy. Interception/fumble return-yardage bonus points and blocked kicks aren't modeled by StatHead for IDP, so they're left out — a minor, usually negligible omission.)

Show this weekly_points value in parentheses next to the IDP starter's status, same style as offense, e.g. "Active (7.42)". Because Dutch Dynasty League's IDP slots are 2 flexible IDP_FLEX slots (any mix of LB/DB/DL), pool ALL of Niek's bench DL/LB/DB players together (not just same-position) when finding the nearest replacement — same nearest-by-absolute-difference logic as the offense FLEX pool, flagging a possible upgrade if the bench player's points are higher. Only say "no bench option with a projection" if no bench IDP player has one.

FantasyPros tiebreaker for close calls (offense and IDP): call mcp__FantasyPros__get_ecr once with position="OP", ranking_type="WEEKLY", scoring="PPR", limit=400 (one superflex pool covering QB/RB/WR/TE, so rank_ecr is comparable across positions) and — only if a Dutch Dynasty League IDP starter is in this slate — once more with position="IDP", ranking_type="WEEKLY", scoring="PPR", limit=250. Match players by name+team. A starter and his nearest bench option are a CLOSE CALL when the bench player's projected points are within 2.0 points of the starter's, or higher. For each close call, compare the two players' rank_ecr (lower = better). ONLY when FantasyPros ranks the bench player better than the starter, add this to the end of that nearest-bench line: " — FantasyPros also prefers <bench player> this week (<bench pos_rank> vs <starter pos_rank>)", e.g. "(WR24 vs WR31)". If FantasyPros agrees with the starter, if it isn't a close call, or if either player is missing from the rankings, add nothing at all. If the connector is unavailable or errors, skip this silently. When one bench player is bundled as the nearest option for several starters (see below), apply the same rule to each of those starters and name only the ones he out-ranks.

Deep-dive line for close calls (OFFENSE only — QB/RB/WR/TE; skip IDP, K, DEF): for each CLOSE CALL as defined in the FantasyPros tiebreaker paragraph (bench player within 2.0 points of the starter, or higher, bench player's game not yet started and not on taxi/IR), add ONE extra line directly under that nearest-bench line. Cap it at the 4 closest calls per league; if there are no close calls, skip this whole paragraph and make none of the calls below.
  (a) Floor/ceiling: for each player in a close call, call mcp__Stathead__get_player_weekly_stats with player_name, season=<season from STEP 0>, fields="player_name,week,fantasy_points_ppr", output_format=csv, and once more with season=<season-1>, week_start=11, week_end=18. Drop games where he clearly had a different role (e.g. under ~2 points in a game he left injured, or games for a different team). Floor = 20th percentile, ceiling = 80th percentile of the remaining games, rounded to whole points. With fewer than 5 usable games, add "(small sample)".
  (b) Matchup: reuse the "matchup" % already in the StatHead weekly-projection rows you fetched above (no extra call).
  (c) Team total: call mcp__Stathead__get_games once with season and week (output_format=jsonl). spread_line > 0 means the HOME team is favoured by that many points. Implied team total: home = (total_line + spread_line) / 2, away = (total_line − spread_line) / 2, rounded to whole points. Skip it if the line is missing.
  (d) Win odds, once per league (only when that league has at least one close call): call mcp__Sleeper_Remote_MCP__get_matchups(league_id, week) to find Niek's opponent this week. For both teams' starters, use actual points (players_points) for players whose game is already final, and the projected points computed above (or StatHead pts) for the rest; sum each side (margin = Niek's total − opponent's). Win probability ≈ Φ(margin / σ), rounded to 5%, where σ = 35 × √(R / T): T = both teams' total projected points for the week, R = the projected points of players whose game has NOT finished yet (so σ = 35 before any games, and shrinks as games are played), with a minimum σ of 8. The 35 was measured on Niek's own leagues (120 matchups: Dutch Dynasty 2025 + 2026, Curacao 2026): projected margins miss the real margin by about 35 points (one standard deviation). Stance: ≥ 60% → favourite, prefer the higher floor; ≤ 40% → underdog, prefer the higher ceiling; otherwise go with the higher projected points.
  (e) Verdict: "Strong", "Lean" or "Toss-up" for one of the two players, using the stance from (d) with matchup/team total as tiebreakers. Also say "Toss-up" when the players are nearly identical on everything.
  Format (plain numbers, no "pts_ppr" label): FOUR separate lines, in this exact shape — a line with just "Deep dive:", then one line per player starting with "• ", then the verdict on its own line starting with "→ ". Example:
    Deep dive:
    • Warren: floor 8 / ceiling 19 · matchup +6% · team total 27
    • Hall: floor 10 / ceiling 15 · matchup −4% · team total 21
    → Lean: start Warren (you're a 35% underdog, so upside wins).
  Never put both players or the verdict on one line. When one bench player is bundled for several starters, give one deep-dive line per starter he's a close call for. If any of these calls fail, leave out only the missing piece; if everything fails, skip the line silently.

If the SAME bench player turns out to be the nearest replacement for more than one starter in the same league (common, since several starters share the same bench pool — e.g. the FLEX pool, or the IDP_FLEX pool), do NOT repeat his full write-up for each starter separately. List each starter's own status line as normal, then add ONE shared line naming that bench player once and which starters he's the closest match for, e.g. "Nearest bench option for Rashee Rice, Kenneth Walker & Sam LaPorta: DK Metcalf (WR, 11.79)" — still flag it as a possible upgrade if his points beat any of those starters'. Only bundle when the exact same bench player recurs for multiple starters; keep the normal one-per-starter line whenever nearest options differ.

For K/DEF starters — just report the status line above and stop there; skip the second line entirely (Niek never rosters a backup K or DEF).

Bench players in this slate (both leagues): the checks above only start from STARTERS in this slate, so they miss the opposite case — a BENCH player whose game is in this slate and who would be a better (or equal) start than a starter who plays LATER this week. After this slate kicks off, that bench player is locked and the chance is gone, so check it now. For each league:
  (1) Candidates: Niek's bench players (not taxi, not IR/reserve) whose NFL team plays in THIS slate and whose game has not started yet (same lock filter as above). Offense (QB/RB/WR/TE) and, in Dutch Dynasty League only, IDP (DL/LB/DB). Skip K/DEF.
  (2) Targets: Niek's starters whose game is LATER than this slate (not in this slate, not yet started). Starters in this slate are already covered above; starters whose game already started or finished are locked and ignored.
  (3) Eligibility: use the same slot rules as above, in reverse. A bench RB/WR/TE can replace a starter in a FLEX slot; a bench QB/RB/WR/TE can replace a SUPER_FLEX starter; a bench player can replace a DEDICATED-slot starter of his own position, or of another position only when Niek has a spare of that starter's position in a FLEX/SUPER_FLEX slot who could slide over (the same "spare" test as above). IDP: any bench DL/LB/DB can replace any IDP starter (IDP_FLEX slots).
  (4) Projections: compute points exactly as above (offense: the three-source average — Sleeper and FantasyPros recomputed with this league's formula, plus StatHead; IDP: the IDP weekly_points method). Reuse the data already fetched; a bench player not in the earlier pulls is matched from the same feeds.
  (5) Flag ONLY a CLOSE CALL: the bench player's points are within 2.0 of an eligible later starter's points, or higher. For each bench candidate, pick the single eligible later starter with the LOWEST projected points and compare against him only. Never give bench players who are not a close call their own entry (only the one-line summary described under Output, when nothing is flagged). Cap at 3 per league, closest (or biggest upgrade) first.
  (6) For each flagged pair, apply the same FantasyPros tiebreaker rule and, for offense, the same Deep-dive line as for the close calls above (they count toward the same cap of 4 deep dives per league, and use the same once-per-league win odds).
Output per league: a short labeled sub-section "Bench player in this slate:" placed after that league's starter entries (or directly under the league name when no starter plays in this slate) and before "Flex order:". One entry per flagged pair: first the comparison line, then the conclusion on its OWN line starting with "→ ", then the Deep dive lines (if any) directly under it, e.g.:
    DK Metcalf (WR, PIT, bench, Thu 02:15) (11.8) vs your FLEX starter Rashee Rice (WR, KC, Sun 19:00) (11.2)
    → Possible upgrade — decide before kickoff tonight, he locks after this game.
  Use "→ Close call — …" instead of "→ Possible upgrade — …" when the bench player is lower but within 2.0. Leave a blank line between flagged pairs. Show kickoff times in Dutch time (Europe/Amsterdam). If a league has no flagged pair, do NOT leave it out silently — always show that the check ran, with ONE short line in the spot where the sub-section would go (no sub-section label, no tiebreaker, no deep dive). If there were candidates: "Bench check: <n> bench player(s) in this slate checked, none close — nearest: <name> (<pos>, <team>) (<pts>) vs <the later starter he was compared with> (<pos>) (<pts>)." Name only the single candidate with the smallest gap, never a list, e.g. "Bench check: 3 bench players in this slate checked, none close — nearest: DK Metcalf (WR, PIT) (8.1) vs Rashee Rice (WR) (14.2)." If none of Niek's bench players play in this slate at all: "Bench check: no bench players in this slate." If he DOES have bench players in this slate but none could be checked, name them and say why instead, e.g. "Bench check: DK Metcalf (WR, PIT) and Deshaun Watson (QB, CLE) are in this slate but already locked (game started)." (other reasons: on taxi, on IR, K/DEF). Never say "no bench players" when he has bench players in this slate. If the check couldn't be done (e.g. projections failed), say "Bench check: couldn't run (<very short reason>)." When a league has no starters in this slate, its body is the line "No starters in this slate (<game(s)>)." followed by a blank line and then either the "Bench player in this slate:" sub-section or this one Bench check line.

IR-stash check — run for BOTH leagues. Both Dutch Dynasty League and Curacao Baller League have a Sleeper reserve/IR slot, but each league restricts WHICH player statuses are actually allowed into it via its own settings — this is NOT the same as a player simply looking hurt or unavailable, and it differs league to league. Separate from the slate cross-reference above, and covers Niek's FULL roster in each league (starters AND bench, not just this slate's game(s)).

For each league, do all of the following:
  (a) Call mcp__Sleeper_Remote_MCP__get_league_info with that league's league_id and read settings.reserve_allow_out, settings.reserve_allow_doubtful, settings.reserve_allow_na, settings.reserve_allow_dnr, and settings.reserve_allow_sus (each is 1 = allowed into the IR slot right now, 0 = not allowed) — these map to a rostered player's Sleeper status being "Out", "Doubtful", "NA", "DNR", or "Sus" respectively. A player whose Sleeper status is literally "IR" is always eligible regardless of these flags. Also read settings.reserve_slots — this is the TOTAL number of IR slots that league has (it differs per league: e.g. Curacao Baller League currently has only 1, Dutch Dynasty League has 5 — never assume a fixed number). Fetch all of this live every time rather than assuming fixed values, since Niek's leagues can change these settings.
  (b) Call mcp__Sleeper_Remote_MCP__get_league_rosters with that league's league_id and find Niek's roster entry — Dutch Dynasty League (1317597867963072512): owner_id "1241383381623644160"; Curacao Baller League (1368762222599213056): owner_id "917568316196233216". For each of his rostered players, read the "status" field directly from THIS Sleeper Remote MCP roster data (Sleeper's own ground-truth status: Active, Out, Questionable, Doubtful, NA, IR, Sus, DNR, etc.) — do NOT use FFC's injuryStatus label for this specific check, since it can be a simplified or misleading proxy (for example, showing a player as generically "Out" when his real Sleeper status is actually "NA" — a materially different, often non-IR-eligible state; FFC's injuryStatus is fine for the slate status line elsewhere in this alert, just not for deciding IR-slot eligibility). Also read that roster's "reserve" array (each entry has player_id and full_name; this is Niek's dedicated IR slot right now for that league, kept separate from starters/bench/taxi by the server itself) AND that roster's "taxi" array (his taxi squad) — the taxi array is needed for the exclusion rule below. If either call errors or the Sleeper Remote MCP connector isn't available, fall back to WebFetch on https://api.sleeper.app/v1/league/<league_id> for settings and https://api.sleeper.app/v1/league/<league_id>/rosters for roster data (using the right league_id), reading the same fields from the raw JSON.

Do NOT rely on FFC's own roster "slot" field for finding who's already on IR — it only ever returns STARTER or BENCH and never distinguishes an IR slot, so it cannot tell you who's already there.

Before checking individual players, first work out how much ROOM that league's IR actually has right now: len(reserve array from step (b)) compared against settings.reserve_slots from step (a). If the reserve array's length is already >= reserve_slots (e.g. Curacao Baller League: reserve_slots is 1, so even a single player already sitting in reserve fills it completely), that league's IR is FULL — do not suggest ANY player for that league's IR-stash section this week, no matter how many players would otherwise qualify below; a suggestion nobody can actually act on isn't useful. Only proceed to the per-player checks below if reserve array length < reserve_slots for that league.

A rostered player qualifies as an IR-stash suggestion ONLY if the league has open IR room per the check above, AND ALL of the following also hold:
  1. His Sleeper status (from the Sleeper Remote MCP roster data — NOT FFC's injuryStatus) is either literally "IR", or one of the statuses that league's settings from step (a) actually allow into the IR slot right now.
  2. His player id does NOT already appear in the reserve array fetched above for that league, AND does NOT appear in that roster's taxi array either. A player on the taxi squad can never be moved directly to the IR/reserve slot in Sleeper — taxi and reserve are mutually exclusive roster designations, so he'd first have to be moved off taxi as a separate transaction before IR is even possible. Treat every taxi-squad player as automatically disqualified from this suggestion regardless of his injury status, even if he'd otherwise clear condition 1.
  3. His lineupLock (from fantasy_get_my_team/fantasy_get_rosters) shows he is NOT locked — lineupLock.status is not "locked" and gameStatus is not "final" or "in_progress". Once a player's own game starts, Sleeper won't let Niek move him until next week no matter what, so flagging an already-locked player is a dead end.
For each player who clears all of the above, note him as a possible move: player name (position, team), his status, and a one-line nudge that moving him to Niek's IR slot would free a normal roster spot for a waiver add. Only include this section for a league if it found something there — omit it entirely for that league if not (whether because nobody qualified or because the IR is already full), don't say "no IR opportunities" or explain that the IR is full.

Flex-order check (both leagues, only for starters whose game has NOT started yet): it's safest to have the EARLIEST-kicking-off players in the dedicated QB/RB/WR/TE slots and the LATEST-kicking-off players in the FLEX and SUPER_FLEX slots, so that if a late player gets hurt or ruled out before his game, Niek can still swap him out through the flexible slot. To check this, map each starter to his exact slot: the "starters" array from mcp__Sleeper_Remote_MCP__get_league_rosters (already fetched for the IR check) is ordered index-by-index to match that league's settings roster_positions / "roster_positions" list from mcp__Sleeper_Remote_MCP__get_league_info (e.g. QB, RB, RB, WR, WR, TE, FLEX, FLEX, SUPER_FLEX, then IDP slots). Get every unlocked starter's kickoff time for this NFL week (from FFC's lineupLock/game info if it includes it, otherwise from this week's NFL schedule via WebSearch). Then look for a fixable pair: a starter X in a FLEX or SUPER_FLEX slot whose game kicks off strictly EARLIER than a starter Y of the SAME position (QB, RB, WR or TE) who sits in a dedicated slot of that position, with both games not yet started. Swapping X and Y keeps the lineup legal and puts the later player in the flexible slot, so suggest it. Also count a SUPER_FLEX QB vs the dedicated QB the same way. Only same-position swaps count (a different-position swap wouldn't keep the dedicated slot legal), players in games already started/finished are ignored, and IDP slots are skipped (they're all flexible already). This covers Niek's whole starting lineup for the rest of the week, not just this slate. If a league has one or more such pairs, add a short labeled sub-section "Flex order:" for that league (after its starter entries, before any IR opportunity sub-section), one line per swap in this style: "Swap <X> (WR, FLEX, Sun 19:00) with <Y> (WR, WR slot, Mon 02:15) — keeps the later game in the flex spot." Show kickoff times in Dutch time (Europe/Amsterdam). If there is nothing to fix in a league, leave the sub-section out entirely — no "flex order is fine" line.

Format: group by league, using each league's Sleeper team name only (no manager username needed), with a blank line separating the two league sections. Under each league, for each relevant starter: one line with name (position, team) and status+points, followed immediately by the second line described above where applicable (projected nearest-replacement for offense or IDP) — K/DEF starters get only the one status line. CRITICAL, easy to miss: put an ACTUAL blank line (a full empty line — two consecutive newlines) BETWEEN each starter's entry, not just between leagues — a past alert came through as one dense unbroken paragraph per league, which is exactly what to avoid; never compress multiple starters into a single paragraph even to save space. After a league's starter section, add a blank line then its IR-stash lines (if the check above found any, for either league) as a short labeled sub-section (e.g. "IR opportunity:"), with a blank line between entries there too if there's more than one — skip this sub-section entirely for a league with none. The "Bench player in this slate:" sub-section (if any) comes right after the starter entries, then the "Flex order:" sub-section (if any), then the IR sub-section, each with the same blank-line spacing. The "Deep dive:" lines (if any — the "Deep dive:" line, the two "• " player lines and the "→ " verdict line) sit directly under the nearest-bench line they belong to, inside the same starter entry (no blank line between them). Reply with the alert content directly — no preamble like "Sent the alert, here's a recap" or other meta commentary about having sent it; start straight in with the first league's name.
