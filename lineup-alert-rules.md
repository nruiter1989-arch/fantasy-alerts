Each scheduled alert (TNF, Sunday early, Sunday late, SNF, MNF) first works out the season, week and which game(s) are in its slate (its STEP 0 and STEP 1), then loads this file and follows everything below for that slate. "This slate" below always means the game(s) the calling alert identified in its STEP 1.

For each such starter, report his active/game status (Sleeper injuryStatus — already visible on the roster entry returned above; active/questionable/doubtful/out/inactive) and flag clearly if he is NOT expected to play.

For each player it knows, it returns practice_details (probability_of_playing as a decimal, and practice_1/practice_2/practice_3 = this week's practice participation, e.g. Full/Limit/DNP) plus player_news. Append a short note to that starter's status line in this style: "Questionable (12.4) — FP: 48% to play, practice Limited/Limited/DNP; <news gist in at most ~12 words>". Then add a second line per starter depending on his position:

Before picking a nearest replacement anywhere below (offense FLEX/SUPER_FLEX/dedicated-slot pools, or the IDP pool), filter the candidate pool to bench players who are actually still swappable right now: check each candidate's lineupLock (from fantasy_get_my_team/fantasy_get_rosters) and drop anyone whose lineupLock.status is "locked", or whose gameStatus is "final" or "in_progress" — his own game has already started, so Niek can't sub him in this week no matter how good his projection looks, and suggesting him isn't actionable. If this empties a pool entirely, fall back to "no bench option with a projection" (or note plainly that everyone in his pool is already locked) rather than naming a locked player.

For OFFENSE starters (QB, RB, WR, TE) — get two independent weekly projections and average them:
  (a) Sleeper's stat-line projection: call mcp__Stathead__get_sleeper_projections once with season=<season from STEP 0>, week=<week from STEP 0>, limit=1000, output_format=jsonl (no position filter — one connector call covers every position, no WebFetch, no popup, no truncation risk) to get each player's projected stat line (pass_yd, pass_td, pass_int, rush_yd, rush_td, rec, rec_yd, rec_td) for the week; match players by name+team. Do NOT use the returned pts_ppr field directly — both of Niek's leagues score interceptions at -1 (not Sleeper's default -2), and Dutch Dynasty League additionally scores passing touchdowns at 6 (not 4), so recompute each player's points from the stat line using the correct formula for whichever league you're reporting on:
    - Dutch Dynasty League (1317597867963072512): points = pass_yd*0.04 + pass_td*6 + pass_int*(-1) + rush_yd*0.1 + rush_td*6 + rec*1 + rec_yd*0.1 + rec_td*6
    - Curacao Baller League (1368762222599213056): points = pass_yd*0.04 + pass_td*4 + pass_int*(-1) + rush_yd*0.1 + rush_td*6 + rec*1 + rec_yd*0.1 + rec_td*6
  (Non-QBs rarely have passing stats, so both formulas reduce to the same line for them — this mainly matters for QBs.)
  (b) StatHead's own weekly projection: call mcp__Stathead__get_weekly_projections once with week=<week from STEP 0>, scoring=ppr, limit=1000, output_format=jsonl (no position filter, no player_name — one call covers the whole player pool) to get each player's opponent-matchup-adjusted "pts" for the week. This is StatHead's own independent model (different from Sleeper's), already scored in full PPR — its weekly feed doesn't expose a raw stat line to recompute from, so this side uses standard scoring rather than Niek's league-specific -1 INT/6-pt-passing-TD weights (this only meaningfully affects QBs; RB/WR/TE rarely have passing stats so it barely matters for them). Match players by name+team.
  Average the two point values per player to get his final projected points. If a player is found in only one of the two sources, use that source's value alone rather than dropping him; only say "no projection available" if he's in neither.

Both leagues' roster_positions include exactly these DEDICATED slots: 1 QB, 2 RB, 2 WR, 1 TE — plus 2 FLEX slots (RB/WR/TE-eligible) and 1 SUPER_FLEX slot (QB/RB/WR/TE-eligible) that aren't tied to one position. Which bench players are actually eligible to replace a given starter depends on which kind of slot he's in — a swap is only real if the resulting lineup can still fill every dedicated slot:
  - Starter in a FLEX or SUPER_FLEX slot: pool = all bench players eligible for that slot (RB/WR/TE for FLEX; QB/RB/WR/TE for SUPER_FLEX), pooled together. Swapping him never threatens the dedicated counts, since he wasn't filling one.
  - Starter in a DEDICATED slot (QB, RB, WR, or TE): first check whether Niek currently starts a "spare" player of that same position already sitting in a FLEX or SUPER_FLEX slot — i.e. does he start MORE players of that position across all slots than the dedicated minimum requires (1 QB, 2 RB, 2 WR, 1 TE)? If yes, that spare could slide into the vacated dedicated slot, so the broader FLEX-eligible pool above is valid for him too. If no such spare exists, ONLY a bench player of that exact same position is a valid nearest-replacement candidate — a different-position bench player can't actually be started there without leaving that dedicated slot unfillable, so exclude every other position from his pool.
  Show the single NEAREST replacement from the correctly-scoped pool — the bench player whose averaged points (computed the same way) are closest in absolute value to the starter's (whether higher or lower) — with name, position, and points. Always show this line; only say "no bench option with a projection" if nobody in the correctly-scoped pool has one. Mark it as a possible upgrade if the bench player's points are actually higher.

For IDP starters (LB, DB, DL) — this only applies in Dutch Dynasty League (Curacao has no IDP roster spots). Do NOT use Sleeper's projections feed or StatHead's weekly projections feed for these — neither reflects this league's IDP scoring. Instead, for each IDP starter AND each bench DL/LB/DB player on the same fantasy team, call mcp__Stathead__get_projections once per player with player_name=<exact name>, position=<their position: DL, LB, or DB>, fields="player_name,team,games,solo,assist,tfl,sack,qb_hit,pd,def_int,ff,fum_rec,def_td,safety,weeks_2plus_sack,weeks_3plus_pd,weeks_10plus_tackle" to get their season projection components (skip a player silently if not found — rare/deep bench/rookie — and note "no projection available" only if he'd otherwise be the closest bench option).

Compute each player's PER-GAME custom IDP projection using Niek's Dutch Dynasty League's actual IDP scoring rules (StatHead's own generic IDP rollup does NOT match these — it has no credit for forced fumbles, pass deflections, or QB hits, and different sack/INT weights):
  weekly_points = (solo/games)*1 + (assist/games)*0.5 + (tfl/games)*2 + (sack/games)*4 + (qb_hit/games)*1 + (def_int/games)*4 + (fum_rec/games)*2 + (ff/games)*3 + (safety/games)*2 + (def_td/games)*6 + (pd/games)*2 + (weeks_10plus_tackle/games)*1 + (weeks_2plus_sack/games)*1 + (weeks_3plus_pd/games)*1
(This uses each player's season-average per-game rate as the week's estimate — StatHead's own docs note IDP week-to-week matchup swings are small, a few percent and near-zero for DB, so a flat season rate is a reasonable weekly proxy. Interception/fumble return-yardage bonus points and blocked kicks aren't modeled by StatHead for IDP, so they're left out — a minor, usually negligible omission.)

Show this weekly_points value in parentheses next to the IDP starter's status, same style as offense, e.g. "Active (7.42)". Because Dutch Dynasty League's IDP slots are 2 flexible IDP_FLEX slots (any mix of LB/DB/DL), pool ALL of Niek's bench DL/LB/DB players together (not just same-position) when finding the nearest replacement — same nearest-by-absolute-difference logic as the offense FLEX pool, flagging a possible upgrade if the bench player's points are higher. Only say "no bench option with a projection" if no bench IDP player has one.

FantasyPros tiebreaker for close calls (offense and IDP): call mcp__FantasyPros__get_ecr once with position="OP", ranking_type="WEEKLY", scoring="PPR", limit=400 (one superflex pool covering QB/RB/WR/TE, so rank_ecr is comparable across positions) and — only if a Dutch Dynasty League IDP starter is in this slate — once more with position="IDP", ranking_type="WEEKLY", scoring="PPR", limit=250. Match players by name+team. A starter and his nearest bench option are a CLOSE CALL when the bench player's projected points are within 2.0 points of the starter's, or higher. For each close call, compare the two players' rank_ecr (lower = better). ONLY when FantasyPros ranks the bench player better than the starter, add this to the end of that nearest-bench line: " — FantasyPros also prefers <bench player> this week (<bench pos_rank> vs <starter pos_rank>)", e.g. "(WR24 vs WR31)". If FantasyPros agrees with the starter, if it isn't a close call, or if either player is missing from the rankings, add nothing at all. If the connector is unavailable or errors, skip this silently. When one bench player is bundled as the nearest option for several starters (see below), apply the same rule to each of those starters and name only the ones he out-ranks.

Deep-dive line for close calls (OFFENSE only — QB/RB/WR/TE; skip IDP, K, DEF): for each CLOSE CALL as defined in the FantasyPros tiebreaker paragraph (bench player within 2.0 points of the starter, or higher, bench player's game not yet started and not on taxi/IR), add ONE extra line directly under that nearest-bench line. Cap it at the 4 closest calls per league; if there are no close calls, skip this whole paragraph and make none of the calls below.
  (a) Floor/ceiling: for each player in a close call, call mcp__Stathead__get_player_weekly_stats with player_name, season=<season from STEP 0>, fields="player_name,week,fantasy_points_ppr", output_format=csv, and once more with season=<season-1>, week_start=11, week_end=18. Drop games where he clearly had a different role (e.g. under ~2 points in a game he left injured, or games for a different team). Floor = 20th percentile, ceiling = 80th percentile of the remaining games, rounded to whole points. With fewer than 5 usable games, add "(small sample)".
  (b) Matchup: reuse the "matchup" % already in the StatHead weekly-projection rows you fetched above (no extra call).
  (c) Team total: call mcp__Stathead__get_games once with season and week (output_format=jsonl). spread_line > 0 means the HOME team is favoured by that many points. Implied team total: home = (total_line + spread_line) / 2, away = (total_line − spread_line) / 2, rounded to whole points. Skip it if the line is missing.
  (d) Win odds, once per league (only when that league has at least one close call): call mcp__Sleeper_Remote_MCP__get_matchups(league_id, week) to find Niek's opponent this week. For both teams' starters, use actual points (players_points) for players whose game is already final, and the projected points computed above (or StatHead pts) for the rest; sum each side. Win probability ≈ Φ(margin / 25), rounded to 5%. Stance: ≥ 60% → favourite, prefer the higher floor; ≤ 40% → underdog, prefer the higher ceiling; otherwise go with the higher projected points.
  (e) Verdict: "Strong", "Lean" or "Toss-up" for one of the two players, using the stance from (d) with matchup/team total as tiebreakers. Also say "Toss-up" when the players are nearly identical on everything.
  Line format (plain numbers, no "pts_ppr" label), e.g.: "Deep dive: Warren floor 8 / ceiling 19 · matchup +6% · team total 27 | Hall floor 10 / ceiling 15 · matchup −4% · team total 21 → Lean: start Warren (you're a 35% underdog, so upside wins)." When one bench player is bundled for several starters, give one deep-dive line per starter he's a close call for. If any of these calls fail, leave out only the missing piece; if everything fails, skip the line silently.

IR-stash check — run for BOTH leagues. Only proceed to the per-player checks below if reserve array length < reserve_slots for that league.

A rostered player qualifies as an IR-stash suggestion ONLY if the league has open IR room per the check above, AND ALL of the following also hold:
  1. His Sleeper status (from the Sleeper Remote MCP roster data — NOT FFC's injuryStatus) is either literally "IR", or one of the statuses that league's settings from step (a) actually allow into the IR slot right now.
  2. His player id does NOT already appear in the reserve array fetched above for that league, AND does NOT appear in that roster's taxi array either. A player on the taxi squad can never be moved directly to the IR/reserve slot in Sleeper — taxi and reserve are mutually exclusive roster designations, so he'd first have to be moved off taxi as a separate transaction before IR is even possible. Treat every taxi-squad player as automatically disqualified from this suggestion regardless of his injury status, even if he'd otherwise clear condition 1.
  3. His lineupLock (from fantasy_get_my_team/fantasy_get_rosters) shows he is NOT locked — lineupLock.status is not "locked" and gameStatus is not "final" or "in_progress". Once a player's own game starts, Sleeper won't let Niek move him until next week no matter what, so flagging an already-locked player is a dead end.

Only include this section for a league if it found something there — omit it entirely for that league if not (whether because nobody qualified or because the IR is already full), don't say "no IR opportunities" or explain that the IR is full.

Flex-order check (both leagues, only for starters whose game has NOT started yet): it's safest to have the EARLIEST-kicking-off players in the dedicated QB/RB/WR/TE slots and the LATEST-kicking-off players in the FLEX and SUPER_FLEX slots, so that if a late player gets hurt or ruled out before his game, Niek can still swap him out through the flexible slot. Get every unlocked starter's kickoff time for this NFL week (from FFC's lineupLock/game info if it includes it, otherwise from this week's NFL schedule via WebSearch). Swapping X and Y keeps the lineup legal and puts the later player in the flexible slot, so suggest it. Also count a SUPER_FLEX QB vs the dedicated QB the same way. Only same-position swaps count (a different-position swap wouldn't keep the dedicated slot legal), players in games already started/finished are ignored, and IDP slots are skipped (they're all flexible already). This covers Niek's whole starting lineup for the rest of the week, not just this slate. If a league has one or more such pairs, add a short labeled sub-section "Flex order:" for that league (after its starter entries, before any IR opportunity sub-section), one line per swap in this style: "Swap <X> (WR, FLEX, Sun 19:00) with <Y> (WR, WR slot, Mon 02:15) — keeps the later game in the flex spot." Show kickoff times in Dutch time (Europe/Amsterdam). If there is nothing to fix in a league, leave the sub-section out entirely — no "flex order is fine" line.
